# Где что лежит

Карта проекта: что хранится локально, что в облаке, что не переносится с кодом.
Полезно, если открываешь проект на другом компьютере/аккаунте.

## 1. Код и документация — в этом репозитории
- Клонируется с GitHub: `annkonwest11-dotcom/unf-reports-automation` (ветка `chore/cleanup`).
- Рабочее ядро: `bot.py`, `sheets.py`, `parser.py`, `sync_42clouds_v2.py`, `run_bot.sh`.
- Документация: `README.md`, `STATUS.md` (текущее состояние + закрытие месяца),
  `docs/СТАВКИ_и_KPI.md` (полный справочник расчёта ЗП и KPI).
- Утилиты сверки: `scripts/payroll_dryrun.py`, `scripts/recon_manager.py`,
  `scripts/check_novye_spravochnik.py`.

## 2. Данные (расчёт ЗП) — в облаке, Google Sheets
Сами цифры живут не в репозитории, а в двух таблицах:
- **Зарплатная** `1KaxfaSWTDR31eAJfmpahaNwaO2Qohrh5xua1Rrjf2Zo` — листы:
  `ДАННЫЕ_Губарев` / `ДАННЫЕ_Перфильев` / `ДАННЫЕ_Володихина` (данные из 1С, лист
  на каждое ИП), `СПРАВОЧНИК` (привязка
  контрагент→менеджер+тип), `НОВЫЕ_КЛИЕНТЫ`, `СМЕНЫ`, `НАСТРОЙКИ` (период, планы),
  `СВОДНАЯ_ЗП` (боевой расчёт) и `СВОДНАЯ_ЗП_TEST` (копия для доработки).
- **KPI (новые продажи)** `1QuvmjSPJUbqGTbGKKBcDu8QdQaFv1Gg2VbzUb-bEbL4` — лист по периоду
  (данные за июнь — на листе «май-июнь»).

Источник данных для листов ДАННЫЕ — **1С:УНФ** (ТРИ базы: Перфильев 152757,
Губарев 64904, Володихина 184621 — подключена 09.10.2026) через OData. Список баз —
`sync_odata.BASES`; те, у кого есть свой лист ДАННЫЕ_*, — `sync_odata.SHEET_BASES`
(только они участвуют во взаиморасчётах и расчёте ЗП).

⚠️ **Беби-листы у клиентов, которые заказывают в ДВУХ базах.** В листах Губарева и
Перфильева колонка J (скорр. оплаты) у беби-клиента ссылается на готовую сумму
`БЕБИ_ЛИСТЫ!J`, а она одна на клиента. Если бы такая же формула стояла и в листе
Володихиной, одна и та же сумма попала бы в расчёт дважды (сентябрь 2026: Иль форно,
SAVVA, Крафт Китчен — 104 597 ₽ фантомных оплат Алёне). Поэтому в
`ДАННЫЕ_Володихина` колонка J считает вычет **пропорционально**, по своим оплатам:
`оплаты − 40% × (оплаты × %беби)`, где `%беби` берётся из `БЕБИ_ЛИСТЫ` (колонка F).
Для клиента, который есть только в одной базе, результат ровно тот же. Примечание об
этом висит на ячейке J3 листа.
Синхронизация перезаписывает суммы (колонки A–E), но НЕ трогает привязку менеджера (F/G,
она приходит из СПРАВОЧНИКА через ВПР) и скорректированную колонку J. Поэтому ручные правки
атрибуции делаются в СПРАВОЧНИКЕ, а корректировки оплат — в колонке J.

## 3. Секреты — только локально (НЕ в git)
- `credentials.json` — ключ сервисного аккаунта Google
  (`sheets-bot@tgbot-sheets-1780773018.iam.gserviceaccount.com`), даёт доступ к таблицам.
- `.env` — токен Telegram-бота, `SPREADSHEET_ID`.
- Оба в `.gitignore`. На новом компьютере их надо скопировать вручную — без них ни бот,
  ни скрипты сверки не подключатся к таблицам.

## 4. Файлы взаиморасчётов (выгрузки из 1С) — на рабочем столе / в загрузках
Excel-файлы «ИЮНЬ 2026 … .xlsx», «Взаиморасчёты … .xlsx» кладутся в `~/Desktop` или
`~/Downloads`. Колонка «Уменьшение долга контрагента» = оплаты за период (= ДАННЫЕ.D).
Скрипт `scripts/recon_manager.py` сверяет такой файл против ДАННЫХ.

## 5. Окружение
- `venv/` — виртуальное окружение Python (в `.gitignore`). На новом компьютере пересоздать:
  `python3 -m venv venv && source venv/bin/activate && pip install -r requirements.txt`.

---

### Чтобы поднять проект на новом компьютере
1. `git clone` репозитория с GitHub.
2. Скопировать `credentials.json` и `.env` в корень (вручную — их нет в git).
3. Создать `venv` и поставить зависимости (см. выше).
4. Прочитать `STATUS.md` — там актуальное состояние и что осталось по закрытию месяца.
