# Борд РОПа — автообновляемый отчёт по продажам

Страница с отчётом отдела продаж, которую пересобирает cron на VPS. Постоянная
ссылка, данные каждые два часа. Появилась 28.09.2026 из статичного отчёта-артефакта
Анны: тот же вид, но цифры тянутся из источников, а не вписываются руками.

## Где что лежит

| Что | Где |
|---|---|
| Сборщик и рендер | `rop_board.py` (на сервере `/opt/salary-bot/rop_board.py`) |
| Шаблон страницы | `templates/rop_board.html` (маркер `/*__DATA__*/` → JSON с данными) |
| Готовая страница | VPS `/data/board/index.html`, рядом `data.json` |
| Кеш разбора комментариев | `rop_board_cache.json` (рядом со скриптом) |
| Лог | `/opt/salary-bot/rop_board.log` |
| Установка / переустановка | `deploy/rop_board_setup.sh` |
| Ссылка | `https://django26666.hostkey.in/b/<токен>/`, токен в `/root/board_token.txt` |

Страницу отдаёт тот же контейнер `nginx-nginx-1` (jonasal/nginx-certbot,
network_mode: host), который уже держит домен VPS с сертификатом Let's Encrypt:
`/data/board` смонтирован в него как `/srv/board:ro`, в конфиге домена добавлен
`location /b/<токен>/`. Путь со случайным токеном вместо пароля — ссылку знает
только тот, кому её дали; `X-Robots-Tag: noindex` закрывает от поисковиков.
Нужен пароль вместо токена — добавить в этот `location` `auth_basic`.

## Откуда данные

| Блок борда | Источник | Как считается |
|---|---|---|
| Оборот | 1С OData, все живые базы | регистр `Продажи` за месяц (`sync_odata.fetch_oborot`) — сходится с отчётом «Продажи» 1С |
| Оплаты | Касса GREENCH | `sync_kassa.fetch_postupleniya` |
| Новые продажи | Google-таблица «ОТЧЕТЫ ПО ПРОДАЖАМ» | сумма колонки менеджера на листе текущего периода (ведётся вручную — решение Анны 28.09.2026) |
| Планы | зарплатная таблица, лист `НАСТРОЙКИ` | отдел — строки РОПа, менеджеры — 210 000, стажёры 105 000 (персональные строки) |
| Дегустации, сделки, статусы | Битрикс24, воронка «Дегустации» (`CATEGORY_ID=0`) | сделки месяца, стадии, комментарии |
| Оборот клиентов менеджера | 1С + `СПРАВОЧНИК` | приход по `РасчетыСПокупателями` клиентов, где менеджер указан как менеджер поиска; конкуренты и закупки исключены |
| Оплаты сопровождения (Алёна) | листы `ДАННЫЕ_*` | сумма колонок D и J по её ресторанам — как формулы СВОДНОЙ C96/C97 |

**Дегустация отправлена** = карточка создана в воронке в этом месяце.
**Сделка в работе** = карточка воронки с движением в этом месяце; закрытые
(провалы, переводы) показаны, но в метрики «в работе / без инфо / без движения»
не идут. Тестовые карточки («ТЕСТ» в названии) в борд не попадают.

## Сопровождение в карточке «Оплаты»

Вторая строка карточки — оплаты ресторанов менеджера сопровождения и его % плана
(`НАСТРОЙКИ!C9`, у Алёны 4 174 949 ₽ — то же число, что в её файле взаиморасчётов).
Повторяет формулы СВОДНОЙ: **% плана считается от оплат ДО вычета беби-листов**
(колонка D листов `ДАННЫЕ_*`), а «в расчёт ЗП» — скорректированные оплаты
(колонка J, беби вычтены). Планы всех менеджеров сопровождения берутся из строк
НАСТРОЕК «Оплаты ресторанов (план)»: появится план у Ии — борд покажет и её.

## Статусы сделок

Статус = стадия воронки, уточнённая разбором последнего комментария менеджера
моделью через OpenRouter (решение Анны 28.09.2026; ключ — тот же, что у
orders-bot). Ответ кешируется по хешу «стадия + комментарий», поэтому обновления
каждые два часа почти ничего не стоят. Нет ключа или модель не ответила — статус
остаётся по стадии, борд не падает.

| Статус | Значение | Базовые стадии |
|---|---|---|
| push | дожать до заказа | Прайс и договор, Первые заказы/контроль |
| meet | нужна встреча / повторная дегустация | по комментарию |
| call | связь, ждём обратную связь | Новая дегустация, Обратная связь получена |
| fill | в карточке нет информации | РАЗОБРАТЬ!!!, пустой комментарий |
| obj | возражение | Цена, Ассортимент, Качество |
| out | провал / перевод | Другое, Перестали работать, Передумали, Не вышли на ЛПР, Связаться позже |

Если модель по комментарию видит, что клиент уже заказывает, а стадия другая —
статус становится `push` с пометкой «в CRM стадия не обновлена».

## Расписание (cron на VPS)

```
0 6 * * *              сборка + сводка со ссылкой Анне (9:00 МСК)
0 8,10,12,14,16 * * *  обновление страницы (11:00–19:00 МСК)
```

Пересчёт вручную:

```bash
cd /opt/salary-bot && TZ=Europe/Moscow venv/bin/python rop_board.py \
    --out /data/board/index.html --json /data/board/data.json
```

Полезные ключи: `--no-llm` (без разбора комментариев), `--print` (сводка в
консоль), `--notify tg|max --url <ссылка>` (сводка Анне), `--json` (только данные).

## Блок «На что обратить внимание»

Считается при каждой сборке: менеджеры ниже 70% темпа месяца, карточки без
информации по менеджерам, сделки без движения дольше 7 дней, дубли карточек в
воронке, недоступные источники (1С, касса), отсутствие листа текущего месяца в
«ОТЧЕТАХ ПО ПРОДАЖАМ», число брошенных сделок в воронке (без движения > 30 дней).

Каждая строка блока **раскрывается** (`<details>`): внутри — конкретные карточки со
ссылками в Битрикс (`https://greench-b24.ru/crm/deal/details/<id>/`), у дублей ссылки
на обе карточки, у отстающих менеджеров — сколько не хватает до плана. Брошенные
сделки показываются по 60 самых свежих из всех (в тексте видно, сколько всего).
Названия стадий берутся из Битрикса (`crm.status.list`), словарь в коде — подстраховка.

Отказ источника не превращается в ноль: в KPI появляется «нет данных» и красный
флаг — правило из [[feedback-soobshat-ob-oshibkah]].

## Что осталось открытым

- ✅ Сводка утром уходит **в MAX** Анне в личку (`MAX_ANNA_CHAT_ID=437065504`,
  `MAX_TOKEN` от obrez-report; переключено скриптом `deploy/rop_board_max.sh` 29.09.2026).
  `WORK_CHAT_ID` бота расходов при этом НЕ меняли — расходы остаются в рабочей группе.
- ⏳ **Маржинальность** — Анна спросила 29.09: 1С себестоимость не ведёт (заполнено 96 строк
  из 6072 за сентябрь), касса даёт движение денег, а не себестоимость. Чтобы вывести на борд,
  нужно разметить статьи кассы на себестоимость / операционные / вне расчёта, добавить
  обрезания и перекуп, прибыль по беби взять из готового отчёта.
- ⏳ **Переход месяца:** листы «ОТЧЕТОВ ПО ПРОДАЖАМ» Анна создаёт вручную. Нет листа с текущим
  месяцем — борд считает по последнему и показывает предупреждение, но цифры будут за прошлый
  период. Проверять 1-го числа.
- Колонка «Оборот его клиентов» осмысленна для Дарьи и Ксении: у новых
  менеджеров в `СПРАВОЧНИКЕ` почти нет закреплённых клиентов, а половина оборота
  висит на «Прямом клиенте» — это видно в примечании под таблицей.
- Новые продажи берутся из ручного листа, поэтому наследуют его ошибки. Сверка с
  1С (первый заказ + окно 30 дней) описана в `docs/ОТЧЕТ_ПРОДАЖ.md` и может быть
  добавлена в борд второй колонкой.
