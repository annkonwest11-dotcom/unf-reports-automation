# README — единый бот УНФ (для терминального ассистента)

Это папка с НОВЫМ прототипом «одного бота» внутри проекта `claude-test` (НЕ
отдельный проект). Цель — со временем заменить разрозненные `bot.py`,
`telegram_reports.py`, `Code.gs` одним ботом: отчёты из 1С по команде, учёт смен
из группы, расчёт зарплаты + KPI, дашборды и авто-сообщения. Прототип собран и
логически протестирован.

> ⚠️ НЕ ЗАПУСКАЙ ДВУХ БОТОВ НА ОДНОМ ТОКЕНЕ.
> Боевой `bot.py` уже работает (polling) на основном BOT_TOKEN. Если запустить
> `bot_prototype.py` с ТЕМ ЖЕ токеном — два процесса будут конфликтовать
> (оба тянут getUpdates → ошибки, потеря сообщений).
> Для проверки логики используй `python bot_prototype.py --selftest` (ничего не
> шлёт, боевого бота не трогает). Для ЖИВОГО теста заведи ОТДЕЛЬНОГО тест-бота у
> @BotFather (новый токен) и тестовую группу, пропиши их в свой `.env`.
> Переключать боевой токен на прототип — только когда он полностью готов и
> старый bot.py остановлен.

## Файлы
- `bot_prototype.py` — рабочий прототип, ВСЁ в одном файле, разбит на 10 секций
  (роутер → клиенты Telegram/Sheets/1С → модули смены/отчёты/зарплата/дашборд).
- `ЧЕК-ЛИСТ_для_бота.md` — заполненный заказчиком бриф: ВСЕ бизнес-правила
  (4 группы оплаты, ставки, подработки, KPI-таблица «поиска», команды, расписание).
  Это источник истины по требованиям.

## Что уже сделано и проверено
- Парсер смены: `смена 25 5 100 рест.1тел:2 250` → структура. ОК.
- Движок зарплаты по группам (EMPLOYEE_GROUP / SHIFT_RATE / SIDE_RATE).
- KPI «поиск»: таблица порогов % плана → фикс-бонус + % от оплат (KPI_TABLE_POISK,
  план 210 000 ₽). Проверено: 110% плана + оплаты 800k → +15 000 + 24 000. ОК.
- Клиент 1С (OData) — единый, с retry/timeout/пагинацией. Команды /today, /range.
- Запуск: простой polling (без webhook — намеренно, был спам).
- Самотест без сети: `python bot_prototype.py --selftest`.

## Уточнено заказчиком (уже в коде)
- Подработки (абсолютные суммы за смену): рест.1тел 1800; рест.2тел 2100
  (1800+300); фирмы 1800; фирмы+1тел 3600; фирмы+2тел 3900. → SIDE_RATE.
- «% от оплат» (KPI «поиска») = от УМЕНЬШЕНИЯ долга контрагентов (поступления)
  по файлу/листу ВЗАИМОРАСЧЁТЫ, в разрезе ответственного менеджера. → _kpi_inputs.
- План «поиска» 210 000 ₽/мес — на КАЖДОГО менеджера, по новым клиентам. → PLAN_POISK.

## Как запустить
```bash
pip install python-telegram-bot==20.7 gspread google-auth requests python-dotenv
# заполнить .env (см. .env.example)
python bot_prototype.py --selftest     # проверка логики без сети
python bot_prototype.py                 # боевой запуск (polling)
```

## .env (секреты — НЕ коммитить)
См. `.env.example`. Значения у Анны уже есть в текущем `.env` проекта
(BOT_TOKEN, SPREADSHEET_ID, ODATA_PASS и т.д.). credentials.json — service account
с доступом к таблице (таблицу расшарить на email из JSON).

## Базы 1С (OData, 42clouds, Basic Auth api_bot)
- Перфильев: https://base.42clouds.com/unf/152757/odata/standard.odata/
- Губарев:   https://base.42clouds.com/unf/64904/odata/standard.odata/

Важное по 1С (из прежней отладки): продажи по полю «Сумма» дают расхождение
с эталоном 1С (70 727 vs 38 050) — проверить определение выручки. Дебиторка:
1С НЕ сворачивает долги с авансами — считать по (Контрагент_Key+Договор_Key),
в долг брать только положительные остатки (цель ИТОГО ≈ 1 457 629).
