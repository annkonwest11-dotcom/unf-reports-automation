# Перенос бота на VPS (чтобы работал 24/7 без ноутбука)

Цель: бот принимает смены круглосуточно, независимо от того, включён твой MacBook или нет.
Ничего в логике бота менять не нужно — он на polling, домен/HTTPS не требуются.

> ⚠️ Пока не выполнишь **шаг 8** (отключение локального бота), НЕ запускай серверного бота
> при работающем локальном — два бота на одном токене дадут ошибку 409. Порядок в инструкции
> уже это учитывает: сначала поднимаем на сервере, проверяем, потом гасим локальный.

---

## Шаг 1. Купить VPS

Провайдер (любой из): **Timeweb Cloud**, **Beget**, **Selectel**, **Reg.ru**.
Минимальная конфигурация с запасом:

- ОС: **Ubuntu 24.04 LTS** (или 22.04)
- 1 CPU, 1 ГБ RAM, 10–15 ГБ диск — этого хватает
- Цена: ~150–300 ₽/мес

После оплаты провайдер пришлёт: **IP-адрес сервера**, **логин** (обычно `root`) и **пароль**
(или предложит SSH-ключ). Держи их под рукой.

---

## Шаг 2. Подключиться к серверу

На своём Mac открой Терминал и подключись (подставь свой IP):

```bash
ssh root@ВАШ_IP
```

Первый раз спросит «Are you sure… (yes/no)» — набери `yes`, затем введи пароль.
Ты внутри сервера, если строка приглашения стала вида `root@...:~#`.

---

## Шаг 3. Установить системные пакеты (на сервере)

Скопируй целиком и выполни:

```bash
apt update && apt -y upgrade
apt -y install python3 python3-venv python3-pip git rsync
```

---

## Шаг 4. Залить код на сервер

Есть два пути. **Путь А (проще)** — заливаем всю папку с Mac напрямую.

**На своём Mac** (в НОВОМ окне терминала, не на сервере) выполни:

```bash
cd /Users/anna/claude-test
rsync -av --exclude venv --exclude '__pycache__' --exclude '_trash' \
      --exclude '*.log' --exclude '.git' \
      ./ root@ВАШ_IP:/opt/salary-bot/
```

Это скопирует код **вместе с секретами** (`.env`, `credentials.json`) и файлами состояния
(`last_update_id.txt`, `employees.json`, `awaiting_name.json`) — они нужны боту и в git не хранятся,
поэтому переносим их именно так.

> Путь Б (через git) не переносит секреты — тогда `.env` и `credentials.json` пришлось бы
> копировать отдельно. Путь А удобнее, используем его.

---

## Шаг 5. Создать окружение Python и поставить зависимости (на сервере)

Вернись в окно, где ты подключён к серверу, и выполни:

```bash
cd /opt/salary-bot
python3 -m venv venv
venv/bin/pip install --upgrade pip
venv/bin/pip install -r requirements.txt
```

Установка selenium пройдёт как обычный пакет — **Chrome для этого не нужен**.
Chrome понадобится только если захочешь запускать синк 1С (`/sync_1c`) на сервере — см. шаг 9 (необязательно).

---

## Шаг 6. Пробный запуск вручную (на сервере)

```bash
cd /opt/salary-bot
venv/bin/python bot.py
```

Если видно, что бот запустился без ошибок (в логе строки про старт / «Recovering … missed updates»
или «No missed updates») — всё хорошо. Останови его пока: **Ctrl+C**.

Если ошибка про токен/доступ — проверь, что `.env` и `credentials.json` доехали:
`ls -la /opt/salary-bot/.env /opt/salary-bot/credentials.json`

---

## Шаг 7. Поставить как автозапускаемую службу (на сервере)

Файл службы уже лежит в проекте (`deploy/salary-bot.service`) и приехал вместе с кодом.
Подключаем его:

```bash
cp /opt/salary-bot/deploy/salary-bot.service /etc/systemd/system/salary-bot.service
systemctl daemon-reload
systemctl enable salary-bot
systemctl start salary-bot
systemctl status salary-bot --no-pager
```

`status` должен показать **active (running)**. Смотреть живой лог:

```bash
journalctl -u salary-bot -f
```

Теперь бот перезапускается сам при перезагрузке сервера и при сбоях.

---

## Шаг 8. Отключить локального бота на Mac (ОБЯЗАТЕЛЬНО)

Только после того, как серверный бот подтверждённо работает. **На своём Mac**:

```bash
launchctl unload ~/Library/LaunchAgents/com.tgbot.sheets.plist
launchctl list | grep tgbot   # должно стать пусто
```

Чтобы он не поднялся снова после перезагрузки Mac, переименуем plist:

```bash
mv ~/Library/LaunchAgents/com.tgbot.sheets.plist ~/Library/LaunchAgents/com.tgbot.sheets.plist.disabled
```

Проверь в Telegram: отправь боту тестовую смену — она должна занестись. Всё, бот больше
не зависит от ноутбука.

---

## Шаг 9 (необязательно). Синк 1С на сервере

Если хочешь, чтобы команда `/sync_1c` работала и на сервере, поставь браузер:

```bash
apt -y install chromium-browser chromium-chromedriver
```

Если синк по-прежнему запускаешь вручную со своего Mac — этот шаг можно пропустить.

---

## Шпаргалка по управлению (на сервере)

| Действие                    | Команда                              |
|-----------------------------|--------------------------------------|
| Статус бота                 | `systemctl status salary-bot`        |
| Перезапустить               | `systemctl restart salary-bot`       |
| Остановить                  | `systemctl stop salary-bot`          |
| Живой лог                   | `journalctl -u salary-bot -f`        |
| Обновить код (с Mac, шаг 4) | тот же `rsync`, затем restart на сервере |

После обновления кода через `rsync` не забудь на сервере: `systemctl restart salary-bot`.
